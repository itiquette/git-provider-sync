=== Development Tools

Go development tools are managed via Go's toolchain. External binary tools (goreleaser, trivy, etc.) need to be installed separately via your package manager.

Key tools include:
- https://github.com/golangci/golangci-lint[golangci-lint] - Go linter aggregator
- https://github.com/vektra/mockery[mockery] - Mock code generator for Go
- https://goreleaser.com/[GoReleaser] - Build and release automation
- https://github.com/anchore/syft[syft] - SBOM generation
- https://github.com/gitleaks/gitleaks[gitleaks] - Secret scanner
- Shell, YAML, and container linters

=== Installing Developer Tools

Install all development tools with a single command:

[source,console]
----
just install
----

This will:
1. Install Go-specific tools via `go install`
2. Check for recommended external tools (which need to be installed separately)

== Development Workflow

=== Just Recipes

We use https://github.com/casey/just[Just] to automate various development tasks. To see all available recipes:

[source,console]
----
just --list
----

[NOTE]
====
* Just recipes are organized by workflow type (linting, building, testing, security)
* For detailed information on each recipe, refer to the link:justfile[justfile]
* Use `just <recipe-name>` to run individual workflows
====

=== Running Tests

Our tests are written in Go's idiomatic table-driven style.

.Run all tests
[source,console]
----
just test
----

.Run tests with coverage
[source,console]
----
just coverage
----

== Code Quality Assurance

=== Local Quality Checks

Before submitting a Pull Request, it's crucial to run the quality checks locally:

[source,console]
----
just default
----

The default workflow runs: clean → tidy → lint → test

TIP: If a check fails, you can run individual checks (e.g., `just lint-go`, `just lint-shell`) to pinpoint and address specific issues.

=== Quality Check Tools

==== Linting
Individual linters provide targeted, fast feedback:
* https://github.com/golangci/golangci-lint[golangci-lint]: Go-specific linters
** Configuration: link:.golangci.yml[.golangci.yml]
* https://github.com/koalaman/shellcheck[shellcheck]: Shell script linter
* https://github.com/google/yamlfmt[yamlfmt]: YAML formatter and linter
* https://github.com/rhysd/actionlint[actionlint]: GitHub Actions workflow linter
* https://github.com/hadolint/hadolint[hadolint]: Dockerfile linter
* https://github.com/gitleaks/gitleaks[gitleaks]: Secret detection

==== License Compliance
* https://github.com/fsfe/reuse-tool[REUSE]: Ensures proper licensing and copyright notices

==== Commit Structure
* https://github.com/siderolabs/conform[Conform]: Checks commit message format

==== Go-specific Checks
* Standard Go tests
* Additional tools: `go vet`, `staticcheck`, `go mod tidy`, `govulncheck`

=== Interpreting Quality Check Results

If any checks fail, follow these steps:

1. Run individual checks to isolate the issue (e.g., `just lint-go`, `just lint-shell`)
2. Use auto-fix where available: `just lint-fix`
3. Carefully review the error messages in your terminal output
4. Consult the documentation for the specific tool that reported the error
5. Address the issues and re-run the checks
6. For CI pipeline failures, reproduce the issue locally, fix it, and update your Pull Request

== Next Steps

Once your development environment is set up:

1. **Explore the codebase**: Start with link:docs/architecture.adoc[Software Architecture Documentation] to understand the project
2. **Run tests**: Execute `just test`
3. **Make changes**: Follow our hexagonal architecture patterns
4. **Test thoroughly**: Use `just verify` before submitting contributions
5. **Submit contributions**: See link:CONTRIBUTING.md[Contributing Guidelines] for pull request process
